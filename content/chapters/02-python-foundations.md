# Python ที่รันซ้ำแล้วได้คำตอบเดิม

กลยุทธ์เดียวกันควรให้ผลเดิมเมื่อใช้ข้อมูลและสมมติฐานเดิม บทนี้สร้างพื้นฐาน Python ที่ช่วยให้เราตรวจว่าความเปลี่ยนแปลงมาจากกติกา ข้อมูล หรือสภาพแวดล้อมของโปรแกรม

เราจะเริ่มจากราคาจำลองเพียงห้าแท่ง แล้วค่อยเพิ่มตาราง ฟังก์ชัน การตรวจคำตอบ และบันทึกการทดลอง ทุกตัวอย่างทำงานในเครื่องและไม่ต้องมีบัญชีโบรกเกอร์

## เป้าหมายและสิ่งที่ต้องเตรียม {#objectives}

เมื่อจบบท คุณจะสร้างสภาพแวดล้อมแยกสำหรับงานวิจัย อ่านตาราง pandas เขียนฟังก์ชันคำนวณ SMA ที่ตรวจข้อมูลขาเข้า และรัน Notebook ใหม่ตั้งแต่ต้นเพื่อยืนยันคำตอบได้

**ก่อนเริ่ม:** รู้จักตัวแปร รายการข้อมูล และคำสั่ง `print()` หากยังไม่คล่อง ให้รันทีละเซลล์และเปรียบเทียบผลกับตารางในบท ไม่จำเป็นต้องจำคำสั่งทั้งหมดก่อนลงมือ

การทำซ้ำได้ หรือ **reproducibility** มีมากกว่าการบันทึกโค้ดหนึ่งไฟล์ ต้องรู้ด้วยว่าใช้ข้อมูลชุดไหน พารามิเตอร์เท่าไร และแพ็กเกจรุ่นใด ข้อความว่า “เครื่องฉันรันได้” ยังไม่ช่วยให้เพื่อนร่วมทีมอธิบายผลที่ต่างกันได้

| ข้อมูล | ราคาจำลอง 5 ค่า เรียงตามเลขแท่ง | ใช้ข้อมูลชุดเดียวกันหรือไม่ |

| ผลที่คาดหวัง | SMA สุดท้าย 102.666667 | คำนวณตามนิยามหรือไม่ |

## แยกห้องทดลองด้วย virtual environment {#environment}

**Virtual environment** คือพื้นที่แยกแพ็กเกจ Python ของโปรเจกต์นี้ออกจากงานอื่น หากงานหนึ่งต้องการ pandas รุ่นเก่า อีกงานต้องการรุ่นใหม่ เราสามารถใช้คนละ environment ได้ โดย `venv` สร้าง environment จาก Python ตัวที่เรียกใช้อยู่ ไม่ได้ติดตั้ง Python รุ่นอื่นให้เอง [เอกสาร Python 3.12](https://docs.python.org/3.12/library/venv.html)

สร้างโฟลเดอร์สำหรับบทเรียน เปิด Terminal ในโฟลเดอร์นั้น แล้วใช้ Python 3.12 ที่ติดตั้งไว้:

```shell
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install numpy==2.5.3 pandas==2.3.2
```

บน Windows คำสั่งสร้าง environment อาจใช้ `py -3.12 -m venv .venv` และเปิดใช้งานใน PowerShell ด้วย `.venv\Scripts\Activate.ps1` ชื่อคำสั่ง Python ขึ้นกับการติดตั้งของเครื่อง

หากต้องการแก้ Notebook ผ่าน Jupyter ให้ติดตั้ง `jupyterlab` เพิ่มใน environment นี้ แล้วเปิดด้วย `python -m jupyter lab` คำสั่งติดตั้งต้องเข้าถึงอินเทอร์เน็ต แต่การคำนวณทุกเซลล์ของบทนี้ทำงานออฟไลน์หลังติดตั้งเสร็จ

```python
import platform
import numpy as np
import pandas as pd

print(platform.python_version())
print(np.__version__)
print(pd.__version__)
```

ไฟล์เรียนฉบับนี้ตรวจด้วย **Python 3.12.14, NumPy 2.5.3, pandas 2.3.2** การระบุเวอร์ชันเป็นบันทึกสภาพแวดล้อมที่ตรวจแล้ว ไม่ใช่ข้อสรุปว่ารุ่นอื่นใช้ไม่ได้ หากเปลี่ยนรุ่น ให้รันการตรวจท้ายบทอีกครั้ง

## จาก list เป็นตารางที่มีความหมาย {#arrays-and-tables}

Python `list` เก็บค่าหลายค่า ส่วน NumPy array ช่วยคำนวณกับตัวเลขทั้งชุด และ pandas Series เพิ่มชื่อกับดัชนีให้ข้อมูล เมื่อรวมหลาย Series ที่ใช้ดัชนีเดียวกัน จะได้ **DataFrame** หรือตารางที่ใช้อธิบายแต่ละขั้นของกลยุทธ์

```python
prices = [100.0, 102.0, 101.0, 104.0, 103.0]
close = pd.Series(
    prices,
    index=pd.RangeIndex(1, 6, name="bar"),
    name="close",
)
data = close.to_frame()
print(data)
```

ข้อมูลชุดนี้สร้างขึ้นเพื่อเรียนรู้ มีหน่วยสมมติเป็น USD เลขแท่ง 1–5 เป็นลำดับข้อมูล ไม่มีวันที่ ตลาด หรือหุ้นจริง และไม่ได้ผ่านการปรับราคาจาก corporate actions

| แท่ง | close | ความเปลี่ยนแปลงจากแท่งก่อน |
| --- | --- | --- |
| 1 | 100.00 | ยังไม่มีราคาก่อนหน้า |
| 2 | 102.00 | เพิ่มขึ้น 2.00 |
| 3 | 101.00 | ลดลง 1.00 |
| 4 | 104.00 | เพิ่มขึ้น 3.00 |
| 5 | 103.00 | ลดลง 1.00 |

ระวังความต่างระหว่าง **ตำแหน่งแถว** กับ **ชื่อดัชนี**: `close.iloc[0]` อ่านแถวแรก ส่วน `close.loc[1]` อ่านดัชนีชื่อ 1 ทั้งคู่ได้ 100 ในตัวอย่างนี้ แต่จะไม่เหมือนกันเสมอเมื่อเปลี่ยนดัชนีเป็นเวลา

pandas จับคู่ Series ตามชื่อดัชนีเมื่อคำนวณ หากราคาและสัญญาณมาจากคนละช่วงเวลา การคูณตารางโดยไม่ตรวจดัชนีอาจได้ค่า `NaN` หรือจับคู่ผิดความตั้งใจ บทถัดไปจะใช้เวลาเป็นดัชนีและตรวจเรื่องนี้โดยตรง

## เขียนกติกาให้เป็นฟังก์ชันที่ตรวจได้ {#functions}

ฟังก์ชันที่ดีสำหรับงานวิจัยควรบอกว่า “รับอะไร คืนอะไร และปฏิเสธอะไร” ฟังก์ชันต่อไปนี้รับราคาบวกที่มีค่าจำกัด และคืนค่าเฉลี่ยย้อนหลังครบหน้าต่าง โดยไม่แก้ข้อมูลต้นฉบับ

```python
def trailing_mean(close, window=3):
    if isinstance(window, bool) or not isinstance(window, int) or window < 1:
        raise ValueError("window must be a positive integer")
    values = pd.Series(close, dtype="float64", copy=True)
    if not np.isfinite(values).all() or (values <= 0).any():
        raise ValueError("prices must be finite and positive")
    if not values.index.is_monotonic_increasing or not values.index.is_unique:
        raise ValueError("index must be ordered and unique")
    return values.rolling(window, min_periods=window).mean()

data["sma3"] = trailing_mean(close, 3)
```

ค่าเฉลี่ย 3 แท่งสุดท้ายคือ:

$$
\operatorname{SMA}_{5,3}=\frac{101+104+103}{3}=102.666667
$$

| แท่ง | close | SMA 3 |
| --- | --- | --- |
| 1 | 100.00 | ยังไม่ครบหน้าต่าง |
| 2 | 102.00 | ยังไม่ครบหน้าต่าง |
| 3 | 101.00 | 101.000000 |
| 4 | 104.00 | 102.333333 |
| 5 | 103.00 | 102.666667 |

`min_periods=window` ระบุชัดว่าต้องมีข้อมูลครบก่อนให้ผลลัพธ์ การเห็น `NaN` ในสองแถวแรกจึงเป็นพฤติกรรมที่ตั้งใจไว้ ไม่ใช่ข้อผิดพลาดที่ควรรีบแทนด้วยศูนย์ [เอกสาร rolling mean](https://pandas.pydata.org/pandas-docs/version/2.3/reference/api/pandas.core.window.rolling.Rolling.mean.html)

## คำนวณผลตอบแทนโดยไม่สับสนหน่วย {#returns}

**ผลตอบแทนแบบธรรมดา (simple return)** วัดการเปลี่ยนแปลงเทียบกับราคาเริ่มต้นของช่วงนั้น ราคาเพิ่ม 2 จากฐาน 100 คือ 2% แต่ลด 1 จากฐาน 102 คือประมาณ −0.980392% ขนาดการเปลี่ยนแปลงเป็นเงินอย่างเดียวจึงยังไม่พอ

$$
r_t=\frac{P_t}{P_{t-1}}-1
$$

```python
data["return"] = close.pct_change(fill_method=None)
total = (1 + data["return"].dropna()).prod() - 1
print(f"{total:.6%}")
```

ผลที่รันได้คือ **3.000000%** ตรงกับ `103 / 100 - 1` ค่า `pct_change()` คืนเป็นสัดส่วน เช่น `0.02` ต้องคูณ 100 หรือใช้รูปแบบ `%` เมื่อต้องการแสดงเป็น 2% [เอกสาร pct_change](https://pandas.pydata.org/pandas-docs/version/2.3/reference/api/pandas.Series.pct_change.html)

ผลตอบแทนหลายช่วงต้องทบกันด้วยผลคูณของ `1 + r` การบวกผลตอบแทนธรรมดาให้ตรง ๆ อาจให้คำตอบต่างจากการเปลี่ยนแปลงของราคาต้นทางถึงปลายทาง และตัวเลข 3% นี้เป็นเพียงการเปลี่ยนแปลงของ **ราคาจำลอง** ยังไม่ใช่ผลตอบแทนกลยุทธ์ เพราะเรายังไม่ได้กำหนดเวลาซื้อ จำนวนหุ้น และต้นทุน

## ทำให้ข้อผิดพลาดส่งเสียง {#verification}

การตรวจด้วย `assert` เหมาะกับเงื่อนไขที่ต้องจริงในแบบฝึกหัด เช่น ช่วงเริ่มต้นยังไม่ควรมี SMA หรือผลตอบแทนสะสมต้องเท่ากับอัตราส่วนราคาปลายทางต่อต้นทาง ฟังก์ชันใช้งานจริงควรใช้ข้อผิดพลาดที่ชัดเจนอย่าง `ValueError` สำหรับ input ที่ใช้ไม่ได้ เพราะ Python สามารถปิด `assert` ในบางโหมดการรันได้

```python
assert data["sma3"].iloc[:2].isna().all()
assert np.isclose(data["sma3"].iloc[-1], 308 / 3)
assert np.isclose(total, close.iloc[-1] / close.iloc[0] - 1)

original = close.copy(deep=True)
_ = trailing_mean(close, 3)
pd.testing.assert_series_equal(close, original)
```

ใช้ `np.isclose()` กับผลคำนวณทศนิยม เพราะคอมพิวเตอร์แทนจำนวนจริงได้ละเอียดจำกัด อย่าสรุปว่ากลยุทธ์ผิดเพียงเพราะผลต่างที่ระดับเศษเล็กมาก และอย่าใช้ tolerance กว้างจนกลบความผิดพลาดระดับที่มีผลต่อการซื้อขาย

ลองป้อนราคาศูนย์หรือกำหนด `window=0` ฟังก์ชันควรปฏิเสธข้อมูลทันที การปล่อยให้ตัวเลขผิดไหลไปจนได้กราฟสวยจะทำให้หาต้นเหตุยากกว่า

## บันทึกการทดลอง และรันใหม่ตั้งแต่ต้น {#reproducibility}

Notebook เก็บทั้งคำอธิบาย โค้ด และผลลัพธ์ แต่สามารถรันเซลล์ข้ามลำดับได้ เมื่อแก้พารามิเตอร์แล้วลืมรันเซลล์ที่ใช้มัน ผลบนหน้าจออาจเป็นผลเก่าที่ดูเหมือนผลใหม่ วิธีตรวจคือเริ่ม kernel ใหม่และรันทุกเซลล์ตามลำดับ

บันทึก **manifest** หรือข้อมูลกำกับการทดลองอย่างน้อย: ชื่อชุดข้อมูล แหล่งที่มา ช่วงเวลา หน่วย เวอร์ชัน พารามิเตอร์ และกติกาที่ใช้ ไฟล์ตัวอย่างยังคำนวณ SHA-256 ของราคาต้นฉบับเพื่อใช้เทียบว่าข้อมูลเปลี่ยนหรือไม่ ค่า hash ไม่ได้พิสูจน์ว่าข้อมูลถูกต้องหรือมาจากตลาดจริง

```python
import hashlib
import json

payload = json.dumps(prices, separators=(",", ":")).encode()
print(hashlib.sha256(payload).hexdigest())
```

สำหรับรายการราคาในบทนี้ ผลคือ `272ac23eed5c4834bbd489be71dfd88fe1d32fa8df6f38868ba068ceb1ab20aa` การจัดรูปแบบ serialization เป็นส่วนหนึ่งของวิธีสร้าง hash จึงควรใช้วิธีเดียวกันเมื่อเปรียบเทียบ

ถ้ามีการสุ่มข้อมูลในบทต่อ ๆ ไป ให้บันทึก seed และวิธีสร้างตัวเลข พร้อมเวอร์ชันของไลบรารีด้วย บทนี้ใช้ข้อมูลกำหนดตายตัว จึงไม่ต้องตั้ง seed

## แบบฝึกหัด: เปลี่ยนเพียงหนึ่งอย่าง {#exercise}

เปลี่ยนราคาปิดแท่งสุดท้ายจาก 103 เป็น 105 โดยคง SMA 3 ไว้ ก่อนรัน ให้คำนวณ SMA สุดท้ายและผลตอบแทนจากแท่งแรกถึงแท่งสุดท้ายด้วยมือ แล้วแก้ assertion ให้ตรงกับการทดลองใหม่

**เฉลย:** SMA สุดท้ายเท่ากับ `(101 + 104 + 105) / 3 = 103.333333` และราคาปลายทางเปลี่ยนไป 5% จาก 100 ค่าของ SMA ในแท่ง 1–4 ต้องไม่เปลี่ยน เพราะเราแก้ข้อมูลที่เกิดภายหลังแท่งเหล่านั้น หากผลก่อนหน้าขยับไปด้วย ควรตรวจการใช้หน้าต่างย้อนหลังและข้อมูลอนาคต

**คำถามต่อยอด:** หากตั้ง SMA 6 กับข้อมูลเพียงห้าแท่ง ควรได้อะไร? คำตอบคือทุกแถวเป็น `NaN` เพราะยังไม่มีหน้าต่างที่ครบหกค่า ไม่ใช่ค่าเฉลี่ยของห้าค่าที่มีอยู่
