# Capstone: Research Dossier

บทสุดท้ายรวมทุกอย่างในคอร์สเป็นเอกสารชิ้นเดียว Research Dossier คือรายงานที่คนอื่นอ่านแล้วตรวจซ้ำได้ว่าเราถามอะไร ใช้ข้อมูลอะไร ลองไปกี่แบบ เลือกอย่างไร และผลในช่วงที่ไม่เคยแตะเป็นอย่างไร ถ้าเพื่อนร่วมงานรันโค้ดของเราแล้วได้ตัวเลขเดิม และเห็นด้วยกับข้อสรุปจากหลักฐานที่ให้ไว้ dossier นั้นก็ทำหน้าที่ของมันแล้ว

หลังจบบท ผู้เรียนจะเขียน Spec Card ครบทุกช่อง เก็บ trial log ตั้งแต่ครั้งแรก freeze กติกาก่อนเปิด holdout หักผลของการเลือกด้วย Deflated Sharpe Ratio และเขียนข้อสรุปที่แยกข้อเท็จจริง สมมติฐาน การตีความ และข้อเสนอออกจากกัน

## Dossier คืออะไร {#dossier-purpose}

dossier เป็นบันทึกการวิจัยที่ตอบคำถามเดียวให้ชัด และบอกขอบเขตของคำตอบนั้น ข้อสรุปว่า "ไม่ควรใช้กฎนี้" เป็นผลลัพธ์ที่ดีพอ ๆ กับข้อสรุปว่า "ควรทดลองต่อใน paper trading" ถ้าหลักฐานรองรับ

ตัวอย่างใน Notebook ใช้ราคาสมมติ 10 ปีที่มี drift ขึ้นเล็กน้อยและไม่มีสัญญาณจังหวะเวลาโดยการออกแบบ กฎ SMA crossover ไม่ควรชนะการซื้อแล้วถือ เราจึงรู้คำตอบที่ถูกล่วงหน้า และใช้มันตรวจว่ากระบวนการของเราพาไปถึงคำตอบนั้นหรือไม่

> เรื่องเล่าจากโลกสมมติ Quantara · หอจดหมายเหตุแห่ง Deltaris
>
> ### สมุดที่เปิดได้ครั้งเดียว
>
> ช่างใหญ่ของ Deltaris เก็บสมุดผลทดสอบเรือของปีสุดท้ายไว้ในตู้ที่มีกุญแจสองดอก เธอถือดอกหนึ่ง หัวหน้าหอจดหมายเหตุถืออีกดอก ใครอยากเปิดต้องยื่นแบบเรือที่เขียนเสร็จแล้วพร้อมลายเซ็น
>
> ลูกมือคนหนึ่งยื่นแบบเรือ เปิดสมุด แล้วพบว่าเรือของเขาช้ากว่าเรือใบธรรมดา เขาขอแก้แบบแล้วเปิดใหม่ หัวหน้าหอส่ายหน้า "เปิดได้ครั้งเดียวต่อหนึ่งแบบ ครั้งที่สองเจ้าจะแก้แบบเรือตามสมุดเล่มนี้ แล้วสมุดก็จะบอกอะไรเกี่ยวกับทะเลไม่ได้อีก" ลูกมือเขียนผลลงในสมุดของตัวเองว่า "แบบที่ 13 ไม่ผ่าน" แล้วกลับไปที่โต๊ะร่าง

## Spec Card ก่อนรันครั้งแรก {#spec-card}

Spec Card ใน Notebook มี 18 ช่อง ฟังก์ชัน `validate_spec` ปฏิเสธ Spec Card ที่ขาดช่องใดช่องหนึ่ง เช่น ถ้าไม่มีช่อง `costs` จะได้ error ทันที เราสร้าง hash จาก Spec Card ทุกครั้ง แล้วแนบ hash ไว้กับทุกบรรทัดใน trial log ถ้า Spec Card เปลี่ยนระหว่างทาง hash จะเปลี่ยน และเราจะเห็นว่า trial ไหนทำภายใต้กติกาชุดไหน

กติกาที่ต้องเขียนก่อนเห็นผลมีสามข้อ

1. **การแบ่งข้อมูล** ปีที่ 1–5 ฝึก ปีที่ 6–7 validation ปีที่ 8–10 holdout
2. **ขอบเขตการค้นหา** SMA เร็ว 5, 10, 20, 50 และ SMA ช้า 50, 100, 200 เฉพาะคู่ที่เร็วน้อยกว่าช้า รวม 11 คู่
3. **กติกาการเลือก** คู่ที่ net Sharpe ใน validation สูงสุด ถ้าเสมอกันให้เลือกคู่ที่ช้ากว่า

## Trial log และ baseline {#trial-log}

Notebook บันทึก 13 trial: SMA 11 คู่ กับ baseline สองแบบ คือถือ 50% แบบสุ่ม และซื้อแล้วถือ ทุกบรรทัดมี Sharpe ช่วงฝึก Sharpe ช่วง validation และ turnover

ในช่วง validation SMA 50/100 ได้ net Sharpe 0.68 ขณะที่ซื้อแล้วถือได้ −0.14 และ SMA อีก 10 คู่ติดลบทั้งหมด ถ้าเราดูเฉพาะแถวที่ชนะ ผลนี้น่าสนใจมาก แต่คู่ 50/100 ได้ Sharpe เพียง 0.13 ในช่วงฝึก อันดับของมันกระโดดจากกลางตารางขึ้นมาที่หนึ่ง เป็นสัญญาณเดียวกับอันดับที่ไม่ข้ามช่วงเวลาใน[บทที่ 5](#/chapter-15)

## หักผลของการเลือก {#deflated-sharpe}

ถ้าลองกฎ 11 แบบที่ไม่มีความสามารถเลย Sharpe สูงสุดก็ยังมักเป็นบวก Bailey และ López de Prado เสนอสูตรประมาณ Sharpe สูงสุดที่คาดว่าจะได้จาก N trial ที่ไม่มีความสามารถ

$$
\mathbb{E}[\max \widehat{SR}] \approx \sqrt{V}\left[(1-\gamma)\,\Phi^{-1}\!\left(1-\tfrac{1}{N}\right) + \gamma\,\Phi^{-1}\!\left(1-\tfrac{1}{N e}\right)\right]
$$

$V$ คือความแปรปรวนของ Sharpe ระหว่าง trial, $\gamma \approx 0.5772$ คือค่าคงที่ Euler-Mascheroni และ $\Phi^{-1}$ คือ inverse ของ normal CDF จากนั้น Deflated Sharpe Ratio (DSR) คือความน่าจะเป็นที่ Sharpe จริงของคู่ที่เลือกสูงกว่าค่านี้ โดยปรับด้วย skewness และ kurtosis ของผลตอบแทน

| | ค่า |
| --- | --- |
| Sharpe สูงสุดที่คาดจาก 11 trial ที่ไม่มีความสามารถ (ต่อปี) | 0.58 |
| Sharpe ของคู่ที่เลือกในช่วง validation (ต่อปี) | 0.68 |
| ความน่าจะเป็นที่ Sharpe จริงมากกว่า 0 | 82.9% |
| Deflated Sharpe Ratio | 55.2% |

ค่า 82.9% ดูน่าเชื่อ แต่ไม่ได้คิดว่าเราเลือกมาจาก 11 แบบ พอหักผลของการเลือก ความน่าจะเป็นเหลือ 55.2% ใกล้กับการโยนเหรียญ งานวิจัยมักใช้เกณฑ์ 95% ตัวเลขนี้จึงบอกตั้งแต่ก่อนเปิด holdout ว่าหลักฐานยังอ่อน

## เปิด Holdout ครั้งเดียว {#holdout}

`HoldoutVault` เก็บข้อมูลทั้งชุดไว้ โค้ดวิจัยเห็นเฉพาะข้อมูลถึงปีที่ 7 การเปิดต้องระบุ hash ของ Spec Card ที่ freeze แล้ว และกฎที่เลือก เปิดได้ครั้งเดียว ครั้งที่สองโยน error พร้อมเหตุผล นอกจากนี้ Notebook ตรวจว่าน้ำหนักของวันในช่วงพัฒนาไม่เปลี่ยนเมื่อมีข้อมูลปีที่ 8–10 เพิ่มเข้ามา เป็น Test 1 จาก[Prework P1](#/chapter-16)

ผลในช่วง holdout 3 ปี

| | SMA 50/100 | ซื้อแล้วถือ |
| --- | --- | --- |
| CAGR gross | −2.49% | |
| CAGR net | −2.64% | 3.11% |
| Volatility | 13.1% | 17.9% |
| Sharpe | −0.14 | 0.26 |
| Max drawdown | −20.7% | −19.6% |
| Turnover ต่อปี | 3.0 | |

ช่วงความเชื่อมั่น 90% ของ Sharpe ช่วง holdout จาก block bootstrap (บล็อก 20 วัน 1,000 รอบ) อยู่ระหว่าง −1.04 ถึง 0.75 กว้างมาก ข้อมูล 3 ปีบอกได้ไม่มากว่า Sharpe จริงเป็นเท่าไร แต่บอกได้ว่ากฎที่ชนะ validation แพ้การซื้อแล้วถือในช่วงที่ไม่เคยแตะ ซึ่งตรงกับความจริงที่เราออกแบบไว้

## เขียนข้อสรุป {#conclusion}

ข้อสรุปแยกเป็นสี่หัวข้อ ห้ามรวมกัน

**ข้อเท็จจริง** ตัวเลขที่รันซ้ำแล้วได้เท่าเดิม เช่น holdout net CAGR −2.64% เทียบกับซื้อแล้วถือ 3.11% DSR 55.2% จาก 11 trial

**สมมติฐาน** สิ่งที่เราตั้งไว้โดยไม่ได้ตรวจ เช่น ต้นทุน 5 bps ต่อการเปลี่ยนน้ำหนัก เงินสดได้ดอกเบี้ย 0% ไม่มีภาษี

**การตีความ** ความเห็นของเราจากข้อเท็จจริง เช่น ผู้ชนะใน validation ไม่มีหลักฐานว่ามีความสามารถหลังหักผลของการเลือก 11 trial

**ข้อเสนอ** สิ่งที่ควรทำต่อ เช่น ไม่นำกฎนี้ไป paper trading บันทึกเป็นไอเดียที่ไม่ผ่าน

Notebook สร้างหน้าแรกของ dossier จากตัวเลขใน cell ก่อนหน้าโดยตรง ไม่มีการพิมพ์ตัวเลขด้วยมือ เมื่อให้ AI ช่วยเรียบเรียง dossier ให้ส่งเฉพาะผลที่ Notebook พิมพ์ออกมา และตรวจว่าทุกตัวเลขในร่างตรงกับผล ตาม[Prework P3](#/chapter-17)
