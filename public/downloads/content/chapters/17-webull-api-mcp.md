# Webull API MCP: ให้ AI อ่านข้อมูลจาก Webull

ใน Prework P2 เราเขียนโค้ดเรียก Webull OpenAPI เอง บทนี้ให้ AI เป็นฝ่ายเรียกผ่าน MCP เราพิมพ์ถามว่า "ขอราคา 5 วันล่าสุด" แล้ว AI ไปดึงข้อมูลมาตอบ สะดวกขึ้นมาก และเพิ่มความเสี่ยงสองเรื่อง คือ AI อาจทำมากกว่าที่เราขอ และอาจสรุปตัวเลขผิดจากข้อมูลที่มันเพิ่งดึงมา

หลังจบบทนี้ ผู้เรียนจะเลือกได้ว่าจะใช้ Cloud MCP หรือ Local MCP ตั้งค่าให้เป็นแบบอ่านอย่างเดียว ตรวจข้อมูลที่ได้ และคำนวณซ้ำทุกตัวเลขที่ AI สรุปให้

## MCP คืออะไร {#what-is-mcp}

MCP ย่อมาจาก Model Context Protocol เป็นมาตรฐานเปิดที่ให้แอป AI เรียก "เครื่องมือ" ภายนอกได้ เครื่องมือแต่ละตัวมีชื่อ คำอธิบาย และ argument เช่น `get_stock_bars_single` รับชื่อหุ้นกับความถี่ แล้วคืนแท่งราคา

เมื่อเราถาม AI ลำดับเหตุการณ์เป็นแบบนี้

1. AI อ่านคำถามแล้วเลือกเครื่องมือที่คิดว่าเหมาะ
2. แอป AI ส่งคำขอไปที่ MCP server ของ Webull
3. Server เรียก Webull OpenAPI ด้วยสิทธิ์ของบัญชีเรา แล้วส่งผลกลับ
4. AI อ่านผลแล้วเขียนคำตอบ

ข้อ 1 และ 4 เป็นงานของโมเดลภาษา จึงผิดได้ ข้อ 2 และ 3 ใช้สิทธิ์จริงของบัญชีเรา เราจึงต้องจำกัดสิทธิ์ตั้งแต่ตอนตั้งค่า ไม่ใช่หวังว่า AI จะเลือกถูก

> เรื่องเล่าจากโลกสมมติ Quantara · หอกลางแห่ง Deltaris
>
> ### กุญแจที่ใหญ่เกินประตู
>
> ช่างมอบกุญแจหอกลางให้หุ่นกล "ไปอ่านบันทึกราคาทองแดงเมื่อวานมาให้ข้า" หุ่นกลับมาพร้อมบันทึก และข่าวดีว่า "ข้าจัดชั้นวางใหม่ให้ด้วย หาของง่ายขึ้นเยอะ"
>
> ช่างเดินไปดูแล้วพบว่าบันทึกของทั้งเมืองเรียงตามสีปก ลูกมือหัวเราะจนต้องนั่งลง วันรุ่งขึ้นช่างทำกุญแจดอกใหม่ ไขได้แค่ตู้อ่าน แล้วแขวนดอกเดิมไว้ในห้องของตัวเอง

## Cloud MCP กับ Local MCP {#cloud-or-local}

Webull มี MCP สองแบบ ข้อมูลในตารางตรวจจากเอกสารเมื่อ 8 พฤศจิกายน 2026

| | Cloud MCP | Local MCP (`webull-openapi-mcp`) |
| --- | --- | --- |
| ติดตั้ง | ไม่ต้องติดตั้ง ใช้ URL `https://api.webull.com/mcp` | รันบนเครื่องเราด้วย `uvx webull-openapi-mcp serve` ต้องมี Python 3.10 ขึ้นไป และ uv |
| ยืนยันตัวตน | OAuth เข้าบัญชี Webull ผ่านหน้าเว็บ | App Key และ App Secret จาก Prework P2 แล้วยืนยันครั้งเดียว token ใช้ได้ 15 วัน |
| เลือกสิทธิ์ | ติ๊กเลือกบัญชีและกลุ่มสิทธิ์: Account Infos, Order Query, Market Data, Security Master | ตั้ง `WEBULL_TOOLSETS` จาก `account`, `market-data`, `trading`, `instrument` |
| เครื่องมือซื้อขาย | รายการเครื่องมือในเอกสาร Cloud MCP เป็น Non-Trading ทั้งหมด | มีเครื่องมือส่ง แก้ และยกเลิกคำสั่ง ถ้าเปิด toolset `trading` |
| สิทธิ์ข้อมูลตลาด | ตามสิทธิ์ในแอป Webull ของบัญชี | ตาม market data subscription ของ OpenAPI |
| สภาพแวดล้อม | บัญชีจริง | ค่าเริ่มต้น `WEBULL_ENVIRONMENT=uat` (sandbox) ต้องตั้ง `prod` เองถ้าจะใช้บัญชีจริง |

หน้า Cloud MCP มีอยู่บนเว็บนักพัฒนาของ Webull Thailand ส่วน README ของ Local MCP ระบุ region ที่รองรับเป็น us, hk, jp, sg, my, uk, mx, br และ za ยังไม่มีไทย ผู้เรียนควรตรวจกับ Webull ว่าบัญชีของตัวเองใช้แบบไหนได้ก่อนเริ่ม

คอร์สนี้ใช้ MCP เพื่ออ่านข้อมูลอย่างเดียว ไม่ส่งคำสั่งซื้อขายผ่าน AI ทุกกรณี การส่งคำสั่งแบบจำลองอยู่ใน[บทที่ 11](#/chapter-24) และใช้ mock broker ที่เราเขียนเอง

## ตั้งค่าแบบอ่านอย่างเดียว {#read-only-setup}

**Cloud MCP** ตอนอนุมัติสิทธิ์ ให้เลือกเฉพาะ Market Data และ Security Master ไม่ต้องเลือก Account Infos หรือ Order Query งานวิจัยในคอร์สไม่ต้องรู้ยอดเงินหรือคำสั่งในบัญชี

**Local MCP** ตั้งค่า toolset ให้เหลือสองกลุ่ม แล้วเก็บ key ไว้นอกไฟล์ตั้งค่าของแอป AI

```json
{
  "mcpServers": {
    "webull": {
      "command": "uvx",
      "args": ["webull-openapi-mcp", "serve", "--env-file", "/path/outside/repo/.env"],
      "env": {
        "WEBULL_TOOLSETS": "market-data,instrument",
        "WEBULL_ENVIRONMENT": "uat"
      }
    }
  }
}
```

ไฟล์ `.env` เก็บ `WEBULL_APP_KEY` และ `WEBULL_APP_SECRET` วางไว้นอกโฟลเดอร์โปรเจกต์ หรือใส่ใน `.gitignore` ห้ามวาง key ในแชตกับ AI และห้าม commit ขึ้น GitHub

ตัวอย่างใน README ของ Webull เขียน key ลงในช่อง `env` ตรง ๆ และตั้ง `WEBULL_ENVIRONMENT` เป็น `prod` วิธีนั้นทำงานได้ แต่ key จะอยู่ในไฟล์ตั้งค่าที่มักถูก sync หรือแชร์ต่อ และถ้าไม่ได้ตั้ง `WEBULL_TOOLSETS` ระบบจะเปิดทุก toolset รวมถึง `trading` ฟังก์ชัน `check_mcp_config` ใน Notebook ตรวจสี่เรื่องนี้ให้

| ปัญหาที่ตรวจ | ตั้งค่าที่ไม่ปลอดภัย | ตั้งค่าของคอร์ส |
| --- | --- | --- |
| Key อยู่ในไฟล์ตั้งค่า | พบ 2 ตัว | ไม่พบ |
| ไม่ได้จำกัด toolset | เปิดทุกกลุ่ม | `market-data,instrument` |
| เปิด `trading` บน `prod` | ใช่ | ไม่ |
| เปิด `account` | ใช่ (เปิดทุกกลุ่ม) | ไม่ |

## เครื่องมือที่ไม่ซื้อขายก็เขียนข้อมูลได้ {#write-tools}

เอกสาร Cloud MCP จัดทุกเครื่องมือเป็น Non-Trading แต่ในนั้นมี `create_watchlist`, `add_watchlist_instruments`, `remove_watchlist_instruments`, `update_watchlist` และ `delete_watchlist` ห้าตัวนี้แก้ watchlist ในบัญชีเราได้ ฝั่ง Local MCP ยังมีเครื่องมือโพสต์ใน community สำหรับบัญชีสหรัฐ

แอป AI ส่วนใหญ่ถามก่อนเรียกเครื่องมือ ให้กดอนุมัติทีละครั้ง และอย่าตั้ง auto-approve กับเครื่องมือที่ขึ้นต้นด้วย `create_`, `update_`, `delete_`, `add_`, `remove_`, `place_`, `modify_` หรือ `cancel_`

## ตรวจข้อมูลก่อนใช้ {#validate-response}

ข้อมูลที่ AI ดึงมาผ่าน MCP ต้องผ่านการตรวจแบบเดียวกับข้อมูลจาก API ที่เราเรียกเอง ก่อนเก็บลงไฟล์หรือใช้ใน backtest

1. คอลัมน์ครบ: time, open, high, low, close, volume
2. เวลามี timezone และเรียงจากเก่าไปใหม่
3. ไม่มีเวลาซ้ำ
4. high สูงกว่าหรือเท่ากับ open และ close ส่วน low ต่ำกว่าหรือเท่ากับทั้งสองค่า
5. volume ไม่ติดลบ

Notebook สร้างข้อมูลที่เสียสามจุด ได้แก่ เวลาซ้ำ high ต่ำกว่า close และ volume หาย `validate_bars` จับได้ครบทั้งสามจุด [บทที่ 2](#/chapter-18) ตรวจเพิ่มเรื่องวันทำการที่หายไปและราคาที่ปรับย้อนหลัง

## คำนวณซ้ำทุกตัวเลขที่ AI สรุป {#verify-claims}

AI อ่านตัวเลขจากข้อมูลจริง แต่ตอนเรียบเรียงคำตอบมันอาจนับผิดหรือปัดเศษผิด ใน Notebook เราสมมติว่า AI ตอบเรื่องหุ้น `DEMO` 5 วันล่าสุด แล้วเทียบกับค่าที่คำนวณเองจากข้อมูลชุดเดียวกัน

| ตัวเลข | AI ตอบ | คำนวณเอง | ผล |
| --- | --- | --- | --- |
| ราคาปิดวันแรก | 100.00 | 100.00 | ตรง |
| ราคาปิดวันสุดท้าย | 103.40 | 103.40 | ตรง |
| ผลตอบแทนช่วง 5 วัน | 3.4% | 3.4% | ตรง |
| ราคาปิดสูงสุด | 103.40 | 103.40 | ตรง |
| จำนวนวันที่ปิดสูงกว่าวันก่อน | 4 | 3 | **ไม่ตรง** |

ห้าวันมีการเปลี่ยนแปลงแค่ 4 ช่วง และวันที่ 3 ปิดต่ำกว่าวันที่ 2 คำตอบ 4 วันจึงผิด ตัวเลขนี้เป็นตัวอย่างที่เราแต่งขึ้นเพื่อสอน ไม่ได้บอกว่า AI ตัวไหนผิดบ่อยแค่ไหน หลักที่ใช้คือ ตัวเลขที่จะเข้าไปในงานวิจัยต้องมาจากโค้ดที่เรารันเอง AI ช่วยดึงข้อมูลและร่างโค้ดได้ แต่ไม่ควรเป็นเครื่องคิดเลขของเรา

## Prompt ที่ใช้กับ MCP {#prompts}

Prompt ที่ดีบอกให้ AI ดึงข้อมูลดิบแล้วบันทึก แทนการขอคำสรุป

```text
ใช้เครื่องมือ get_stock_bars_single ดึงแท่งราคารายวันของ SPY 30 แท่งล่าสุด
บันทึกผลเป็น CSV คอลัมน์ time, open, high, low, close, volume โดยคงเวลาตามที่ได้รับ
บอกจำนวนแถว เวลาแถวแรกและแถวสุดท้าย และ timezone ของเวลา
ห้ามเรียกเครื่องมืออื่น ห้ามสรุปผลตอบแทนหรือแนะนำการลงทุน
```

จากนั้นใช้ Notebook ของบทนี้ตรวจไฟล์ CSV ก่อนใช้งานต่อ

## เก็บ audit log {#audit-log}

ทุกครั้งที่ AI เรียกเครื่องมือ ให้จดเวลา ชื่อเครื่องมือ argument และจำนวนแถวที่ได้ แต่ไม่จด key, secret หรือ token Local MCP ของ Webull มีตัวเลือก `WEBULL_AUDIT_LOG_FILE` สำหรับคำสั่งซื้อขาย ส่วนการอ่านข้อมูลในคอร์สนี้เราจดเองแบบในตัวอย่าง

```json
{"time": "2026-11-08T09:30:00+00:00", "tool": "get_stock_bars_single",
 "args": {"symbol": "DEMO", "timespan": "D", "count": 5}, "rows": 5}
```

Log นี้ใช้ตอบคำถามภายหลังว่าข้อมูลชุดไหนมาจากไหน ดึงเมื่อไร ซึ่งเป็นข้อมูลที่ต้องใส่ใน Research Dossier ของ[บทที่ 12](#/chapter-25)
