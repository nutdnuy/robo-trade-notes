# ให้โมเดลเรียนรู้ โดยไม่แอบเห็นอนาคต

Machine Learning เพิ่มวิธีสร้างสัญญาณ แต่ไม่ได้ยกเลิกกฎเรื่องเวลา บทนี้สร้างโมเดลทำนายทิศทางแบบเล็กที่ตรวจได้ทุกขั้น ตั้งแต่ feature และ label ไปจนถึงผลทดสอบที่แยกออกจากการเลือกโมเดล

## เริ่มที่คำถาม ไม่ใช่ชื่อโมเดล {#objectives}

คำถามของเราคือ **“หลังรู้ผลตอบแทนสาม session ล่าสุดแล้ว session ถัดไปจะเป็นบวกหรือไม่?”** โมเดลต้องให้คำตอบโดยเห็นข้อมูลได้เท่าที่ผู้ใช้เห็น ณ เวลาตัดสินใจเท่านั้น

เมื่อเรียนจบ คุณจะจัดตาราง feature/label ตามเวลา fit ค่าปรับสเกลด้วย training data เท่านั้น เลือกพารามิเตอร์บน validation และเปรียบเทียบโมเดลกับ baseline ที่เรียบง่ายบน final test

**พื้นฐานที่ใช้:** pandas, ผลตอบแทนรายช่วง, แนวคิดการแยกชุดข้อมูลในบท 5 และการแยก signal ออกจาก fill ไม่ต้องเคยใช้ไลบรารี Machine Learning ตัวอย่างใช้ NumPy แก้สมการเชิงเส้นโดยตรง เพื่อให้เห็นสิ่งที่ถูกเรียนรู้ชัดเจน

Hilpisch บท 5 หน้า 132–134 และ 146 แสดงแนวคิด lagged returns และการทำนายทิศทาง เรานำแนวคิดมาออกแบบตัวอย่างใหม่ โดยเพิ่มการแบ่งเวลา ช่องว่างระหว่างชุด และการตรวจ preprocessing แยกจากข้อมูลอนาคต [แหล่งอ้างอิง](#references)

## สร้างข้อมูลที่รู้ที่มาแน่นอน {#data}

ข้อมูลมี **420 session สังเคราะห์** เลข 0–419 เป็น index ใน Python ไม่ใช่วันที่ซื้อขาย เริ่มราคาที่ 100 USD สมมติไม่มี corporate actions และไม่มีการเปลี่ยนราคาระหว่างปิดกับเปิดวันถัดไป ไม่มี timezone หรือตลาดจริงเกี่ยวข้อง

กำหนดผลตอบแทนตั้งต้น $r_0=0$ และสร้างช่วงถัดไปด้วย

$$
r_t=0.25r_{t-1}+\epsilon_t, \qquad \epsilon_t\sim N(0,0.012^2)
$$

ค่า 0.25 ใส่ความสัมพันธ์กับผลตอบแทนก่อนหน้าไว้ **โดยตั้งใจ** เพื่อให้มีโจทย์ให้โมเดลลองเรียน ส่วน noise ทำให้คำตอบไม่แน่นอน เราใช้ random seed 7 เพื่อให้ทุกคนรันซ้ำได้ เหตุผลนี้ไม่ได้บอกว่าหุ้นจริงมีความสัมพันธ์แบบเดียวกัน

```python
rng = np.random.default_rng(7)
returns = np.zeros(420)
noise = rng.normal(0, .012, len(returns))
for t in range(1, len(returns)):
    returns[t] = .25 * returns[t - 1] + noise[t]

closes = 100 * np.cumprod(1 + returns)
opens = np.r_[100, closes[:-1]]
```

ราคาปิดสุดท้ายของชุดที่รันได้เท่ากับ **52.239133 USD** เส้นทางนี้เป็นหนึ่งตัวอย่างสุ่มที่ตรึงไว้ ไม่ใช่ประวัติหุ้นหรือการคาดการณ์ราคา เราไม่เปลี่ยน seed เพื่อหากราฟที่ดูดี

## Feature กับ label อยู่คนละเวลา {#features}

**Feature** คือข้อมูลที่ป้อนให้โมเดล ส่วน **label** คือคำตอบจริงที่จะใช้สอนและประเมิน ในบทนี้ feature ของการตัดสินใจหลังปิด session $t$ มีสามค่า:

$$
x_t=(r_t,r_{t-1},r_{t-2}), \qquad
y_t=\begin{cases}+1&r_{t+1}>0\\-1&r_{t+1}\le0\end{cases}
$$

| สิ่งที่อยู่ในแถวเวลา t | รู้เมื่อไร | ใช้ทำอะไร |
| --- | --- | --- |
| `r0 = r_t` | หลังปิด t | feature ล่าสุด |
| `r1 = r_(t-1)` | รู้แล้วตั้งแต่ก่อนหน้า | feature ย้อนหนึ่งช่วง |
| `r2 = r_(t-2)` | รู้แล้วตั้งแต่ก่อนหน้า | feature ย้อนสองช่วง |
| `y` | หลังปิด t+1 | label สำหรับฝึก/ตรวจภายหลัง |
| `future_return` | หลังปิด t+1 | คำนวณผลที่เกิดหลังสัญญาณ |

เมื่อตัดแถวที่ยังมี lag ไม่ครบและแถวสุดท้ายที่ยังไม่มีอนาคต จะเหลือ **417 ตัวอย่าง** จาก decision session 2–418 โค้ดสร้าง feature จากฝั่งอดีตเท่านั้น และไม่ใส่ `future_return` ลงในรายชื่อ feature

หากจะซื้อขาย สัญญาณหลังปิด $t$ ใช้สั่งที่เปิด $t+1$ แล้ววัดผลถึงปิด $t+1$ ได้ภายใต้สมมติฐาน fill ของตัวอย่างนี้ การวัดผลจากเปิด $t$ ถึงปิด $t$ จะใช้ข้อมูลที่เกิดก่อนสัญญาณและผิดเวลา

## แบ่งอดีตกับอนาคตก่อน fit ทุกอย่าง {#split}

เรียงข้อมูลตามเวลา แล้วกำหนดขอบเขตไว้ล่วงหน้า:

| ชุด | จำนวนแถว | Decision session | ช่วงที่ label เกิด |
| --- | ---: | --- | --- |
| Train | 240 | 2–241 | 3–242 |
| Validation | 80 | 243–322 | 244–323 |
| Final test | 95 | 324–418 | 325–419 |

เว้น decision session 242 และ 323 ไม่ใช้ในชุดใด เพื่อให้ label ของชุดก่อนจบก่อนการตัดสินใจแถวแรกของชุดถัดไปอย่างชัดเจน ความยาวช่องว่างในงานจริงต้องพิจารณาช่วงอนาคตที่ label ครอบคลุม ไม่ควรใช้หนึ่งแถวเหมือนกันทุกโจทย์ [TimeSeriesSplit](https://scikit-learn.org/stable/modules/generated/sklearn.model_selection.TimeSeriesSplit.html)

**Standardization** คือการลบค่าเฉลี่ยแล้วหารส่วนเบี่ยงเบนมาตรฐานของแต่ละ feature เราคำนวณทั้งสองค่าจาก train แล้วใช้ค่าชุดเดิมแปลง validation และ test

```python
mu = X[train_idx].mean(axis=0)
sigma = X[train_idx].std(axis=0, ddof=0)
sigma = np.where(sigma == 0, 1.0, sigma)
Z = np.column_stack([np.ones(len(X)), (X - mu) / sigma])
```

ค่าเฉลี่ย train ของ feature สามตัวคือ `[-0.00238319, -0.00239514, -0.00235402]` ห้ามใช้ค่าเฉลี่ยของข้อมูลทั้งหมด แม้จะไม่ได้ดู label ก็ตาม เพราะการกระจายตัวของอนาคตก็เป็นข้อมูลที่ยังไม่ควรรู้ [แนวทางป้องกัน data leakage](https://scikit-learn.org/stable/common_pitfalls.html#data-leakage)

คอลัมน์หนึ่งที่เพิ่มหน้าตารางคือ intercept หรือค่าคงที่ของโมเดล ข้อมูล validation/test อาจมีค่าเฉลี่ยหลังแปลงไม่เท่ากับศูนย์ ซึ่งเป็นเรื่องปกติ ไม่ใช่เหตุผลให้คำนวณสเกลใหม่บน test

## โมเดลเล็กที่ตรวจสมการได้ {#model}

เราใช้การถดถอยแบบ **ridge** กับ label -1/+1 แล้วแบ่งทิศทางจากเครื่องหมายของคะแนน หลักการคือหาน้ำหนักที่พยายามประมาณ label พร้อมจำกัดขนาดน้ำหนักด้วยพารามิเตอร์ $\alpha$

$$
\hat\beta=(Z_{\text{train}}^T Z_{\text{train}}+\alpha P)^{-1}Z_{\text{train}}^T y_{\text{train}}
$$

$P$ เป็นเมทริกซ์แนวทแยงที่มีค่า 0 ตรง intercept และ 1 ตรง feature อื่น หมายความว่าไม่ลงโทษค่าคงที่ ในโค้ดใช้ `np.linalg.solve` แก้ระบบสมการโดยตรง แทนการสร้าง inverse เอง [NumPy](https://numpy.org/doc/stable/reference/generated/numpy.linalg.solve.html)

```python
penalty = np.eye(design.shape[1]) * alpha
penalty[0, 0] = 0
coef = np.linalg.solve(
    design.T @ design + penalty,
    design.T @ labels
)
prediction = np.where(Z_new @ coef > 0, 1, -1)
```

คะแนน `Z_new @ coef` ไม่ใช่ความน่าจะเป็นที่ผ่านการปรับเทียบ และโมเดลนี้ไม่ใช่ logistic regression ถ้าคะแนนเป็น 0.8 จึงไม่ควรพูดว่าโอกาสขึ้น 80%

กำหนดตัวเลือก $\alpha$ ไว้เพียง 0.1, 1, 10 และ 100 เลือกด้วย **balanced accuracy** บน validation ซึ่งเฉลี่ย recall ของกลุ่มลงและกลุ่มขึ้น หากเท่ากันให้เลือกค่าที่ลงโทษแรงกว่า กฎตัดสินเสมอนี้ถูกกำหนดก่อนเปิด test

| Alpha | Accuracy บน validation | Balanced accuracy |
| --- | ---: | ---: |
| 0.1 | 55.0% | 55.0% |
| 1.0 | 55.0% | 55.0% |
| 10.0 | 52.5% | 52.5% |
| 100.0 | 50.0% | 50.0% |

เลือก **alpha = 1** แล้วตรึงค่าเฉลี่ย สเกล น้ำหนัก และ threshold 0 ไว้ โมเดลตัวอย่างไม่ refit หลังเลือก จึงยังใช้ข้อมูล train 240 แถวในการเรียนรู้พารามิเตอร์

## เปิด final test แล้วอ่านทั้งจุดแข็งและจุดอ่อน {#evaluation}

เปรียบเทียบกับสองวิธีที่ไม่ต้อง fit น้ำหนัก: **training majority** ทายทิศที่พบมากที่สุดใน train ทุกครั้ง และ **persistence** ทายว่าช่วงถัดไปมีทิศเหมือนผลตอบแทนล่าสุด ทั้งสามวิธีใช้ final test 95 แถวชุดเดียวกัน

| วิธี | Accuracy | Balanced accuracy |
| --- | ---: | ---: |
| Ridge ที่เลือกแล้ว | 54.7368% | 55.1197% |
| ทายกลุ่มส่วนใหญ่ของ train | 49.4737% | 50.0000% |
| ทายทิศเหมือนช่วงล่าสุด | 55.7895% | 55.7846% |

โมเดลทายถูก 52 จาก 95 แถว แต่ **ยังด้อยกว่าวิธี persistence** บนตัวชี้วัดทั้งสอง การเพิ่มขั้นตอนเรียนรู้จึงยังไม่ได้แสดงข้อได้เปรียบด้านความแม่นในชุดนี้

ตาราง **confusion matrix** แยกให้เห็นว่าโมเดลผิดแบบใด:

| ผลจริง / คำทำนาย | ทายลง | ทายขึ้น |
| --- | ---: | ---: |
| ลงจริง | 43 | 4 |
| ขึ้นจริง | 39 | 9 |

โมเดลทายลงเป็นส่วนใหญ่ แม้จับลงจริงได้ 43 จาก 47 แถว แต่จับขึ้นจริงได้เพียง 9 จาก 48 แถว นี่เป็นข้อจำกัดที่ตัวเลข accuracy ค่าเดียวซ่อนไว้ เรารายงานมันโดยไม่เปลี่ยน threshold ให้ผล test ดูดีขึ้น

### ความแม่นกับกำไรตอบคนละคำถาม

เพื่อเชื่อมกลับสู่ระบบซื้อขาย ลองใช้คำทำนายขึ้นเป็น Long และลงเป็น Cash เริ่ม final test ด้วยเงินสด ใช้หุ้นเศษส่วน ลงทุนทั้งพอร์ตหลังต้นทุน ไม่ชอร์ต ไม่รับดอกเบี้ย หักต้นทุน 10 bps จากมูลค่าพอร์ตก่อนการเข้า/ออกแต่ละครั้งตามแบบจำลองบท 5 และขายหุ้นคงเหลือหลัง session สุดท้าย ฐานต้นทุนนี้ไม่ใช่มูลค่าหุ้นที่ซื้อขายหลังค่าบริการตามแบบจำลองบท 4

| วิธีบนช่วง test เท่านั้น | ผลตอบแทนสุทธิจำลอง | Max drawdown | สัดส่วนช่วงที่ Long | จำนวนการเข้า/ออก |
| --- | ---: | ---: | ---: | ---: |
| Ridge Long/Cash | 4.1508% | -2.2250% | 13.6842% | 20 |
| Long ตลอดช่วง | -0.2470% | -13.8346% | 100% | 2 |
| Cash ไม่มีดอกเบี้ย | 0% | 0% | 0% | 0 |

ความแม่นนับแต่ละแถวเท่ากัน แต่กำไรขาดทุนขึ้นกับขนาดการเคลื่อนไหว ช่วงที่ลงทุน และต้นทุน จึงอาจจัดอันดับวิธีไม่เหมือนกัน ผลบวกของ Long/Cash ในเส้นทางสังเคราะห์เดียวไม่ได้ยืนยันว่าระบบทำนายตลาดจริงได้ ต้องเพิ่มการประเมินบนข้อมูลจริงที่ตรวจแล้ว หลายช่วงเวลา และสมมติฐาน fill ที่เหมาะสมโดยเก็บ final test ใหม่ไว้

## แบบฝึกหัด: ตรวจว่าอนาคตไหลกลับเข้าการฝึกหรือไม่ {#exercise}

ลองแก้ feature เฉพาะแถว test ให้ใหญ่ขึ้น 1,000 หน่วย แล้วคำนวณค่าเฉลี่ย train ใหม่ ควรเปลี่ยนหรือไม่? จากนั้นอธิบายว่าทำไมคำทำนายบน test ที่ถูกแก้อาจเปลี่ยนได้ แม้โมเดลไม่เปลี่ยน

```python
tampered = X.copy()
tampered[test_idx] += 1000
assert np.array_equal(tampered[train_idx].mean(axis=0), mu)
```

**เฉลย:** ค่าเฉลี่ย train และโมเดลต้องคงเดิม เพราะไม่ได้อ่านแถว test ตอน fit แต่คำทำนายบนข้อมูลที่แก้แล้วเปลี่ยนได้ เนื่องจาก input ที่จะทำนายเปลี่ยน ไม่ใช่เพราะระบบได้เรียนรู้น้ำหนักใหม่

อีกข้อหนึ่ง: ถ้าเปลี่ยน label เป็นทิศทางสะสม 5 session ถัดไป ควรเว้นช่องว่างหนึ่งแถวเหมือนเดิมทันทีหรือไม่?

**เฉลย:** ไม่ควร ต้องตรวจช่วงเวลาที่แต่ละ label ครอบคลุม แล้วกันแถวฝึกที่ผลลัพธ์ทับกับช่วงตัดสินใจประเมิน ในงานนี้ gap ถูกเลือกจาก horizon 1 session ไม่ใช่ค่ามาตรฐานสำหรับทุกโมเดล

Notebook ตรวจขอบเขตเวลาก่อนรัน ตรวจว่า feature แต่ละแถวเกิดไม่ช้ากว่า decision session ตรวจว่า label ตรงกับผลตอบแทนเปิดถึงปิดของ session ถัดไป และตรวจว่าจำนวนช่องใน confusion matrix รวมกันเท่ากับ 95
