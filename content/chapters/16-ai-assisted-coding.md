# ใช้ AI เขียนและตรวจโค้ด Python

ทุกวันนี้น้อยคนจะพิมพ์ backtest เองทุกบรรทัด เราพิมพ์บอก AI แล้วได้โค้ดกลับมาในไม่กี่วินาที ปัญหาคือโค้ดที่รันผ่านกับโค้ดที่ถูกกติกาเป็นคนละเรื่องกัน บทนี้ฝึกงานที่ AI ทำแทนเราไม่ได้ คือเขียนกติกาให้ชัด ตรวจผล และจดว่าลองอะไรไปแล้วบ้าง

หลังจบบทนี้ ผู้เรียนจะเขียน prompt ที่บอกเวลาใช้สัญญาณและต้นทุนครบ อ่านโค้ดร่างแล้วรู้ว่าต้องสงสัยตรงไหน และเขียน test สองแบบที่จับ look-ahead ได้

## วงจรทำงานกับ AI {#ai-workflow}

เราใช้วงจรเดียวกันทั้งคอร์ส ไม่ว่าจะใช้ Claude Code, Codex, Cursor หรือ ChatGPT

1. **เขียน Spec Card ก่อน** บอกข้อมูล ความถี่ เวลาที่รู้สัญญาณ ราคาที่ใช้ซื้อขาย ต้นทุน และ benchmark ใช้โครง 7 ข้อจาก[บทที่ 1](#/chapter-12) เพิ่มรายชื่อหุ้น timezone และแหล่งราคาที่ปรับแล้ว
2. **ส่ง prompt ที่อ้าง Spec Card** และบอกสิ่งที่ห้ามทำให้ชัด
3. **อ่านโค้ดร่างโดยมีคำถามในใจ** สัญญาณใช้ข้อมูลถึงแท่งไหน ซื้อขายที่ราคาไหน ต้นทุนหักตรงไหน แถวไหนหายไป
4. **รัน test ที่เราเขียนเอง** อย่าใช้ test ที่ AI เขียนมาพร้อมโค้ดเป็นหลักฐานเพียงชิ้นเดียว เพราะมันมักทดสอบสิ่งที่โค้ดทำอยู่แล้ว ไม่ได้ทดสอบกติกาที่เราต้องการ
5. **จดหนึ่งบรรทัดใน trial log** ทุกครั้งที่รัน แม้ผลจะแย่

ขั้นที่ 1, 4 และ 5 เป็นงานของเรา AI ช่วยร่าง test ได้ แต่ต้องอ่านทุกบรรทัดว่ามันทดสอบกติกาที่เราตั้งจริง

## Prompt ที่บอกกติกาครบ {#prompt}

Prompt สั้น ๆ อย่าง "เขียน backtest SMA crossover ให้หน่อย" บังคับให้ AI เดาเรื่องสำคัญเกือบทั้งหมด เช่น ใช้ close หรือ open ซื้อขายวันไหน คิดต้นทุนไหม annualize ด้วยกี่วัน ทุกการเดาคือจุดที่ผลอาจผิดโดยไม่มี error ให้เห็น

Prompt ในไฟล์ `lesson_16.py` ระบุเจ็ดเรื่อง

| เรื่อง | ข้อความใน prompt | ถ้าไม่บอก AI มักเลือก |
| --- | --- | --- |
| บทบาทและเครื่องมือ | Python standard library | ติดตั้ง library ที่เราไม่มี |
| ข้อมูล | day, open, close สมมติ รายวัน ไม่มีช่องว่าง | สมมติว่ามีคอลัมน์ `Adj Close` |
| เวลาของสัญญาณ | สัญญาณจาก close วัน t ซื้อที่ open t+1 ถือถึง open t+2 | ใช้ close วัน t ทั้งตัดสินใจและรับผล |
| ต้นทุน | 5 bps ทุกครั้งที่น้ำหนักเปลี่ยน | ไม่คิดต้นทุน |
| รูปแบบผลลัพธ์ | หนึ่งแถวต่อช่วงถือ พร้อม gross และ net | คืนตัวเลขเดียว |
| สิ่งที่ห้าม | ห้ามทิ้งแถวเงียบ ๆ ห้ามใช้ 365 วัน ห้ามเรียก API | `dropna()` ทั้งตาราง, √365 |
| Test ที่ต้องมี | test สองแบบตามหัวข้อถัดไป | test ที่แค่เช็กว่าฟังก์ชันคืน list |

เมื่อใช้ pandas ประโยคเรื่องเวลาจะกลายเป็นการเลื่อนข้อมูล เช่น `signal.shift(1)` สำหรับน้ำหนักที่ใช้ในแท่งถัดไป เราต้องอ่านทิศของ `shift` ทุกครั้ง เพราะ `shift(-1)` ดึงค่าจากอนาคตกลับมา

## โค้ดร่างที่รันผ่านแต่ผิดกติกา {#draft-review}

ฟังก์ชัน `draft_backtest` ในไฟล์เป็นแบบที่ AI มักส่งกลับมาเมื่อ prompt ไม่ระบุเวลา

```python
for t in range(1, len(bars)):
    signal = 1.0 if avg[t] is not None and closes[t] > avg[t] else 0.0   # close t
    returns.append(signal * (closes[t] / closes[t - 1] - 1))            # close t-1 -> t
```

บรรทัดแรกตัดสินใจจาก close วัน t บรรทัดที่สองให้ผลตอบแทนจาก close วัน t−1 ถึง close วัน t ผลตอบแทนนี้เกิดขึ้นก่อนที่เราจะรู้สัญญาณ วันที่ราคาขึ้นแรงมักเป็นวันที่ close ทะลุเส้นค่าเฉลี่ย โค้ดจึงเก็บวันขึ้นแรงไว้และหลบวันลงแรง

บนราคาสมมติ 300 วันชุดเดียวกัน

| วิธีคำนวณ | ผลตอบแทนสะสม |
| --- | --- |
| ฉบับร่าง (ใช้ close วันเดียวกัน) | 82.3% |
| ฉบับตรวจแล้ว gross (open t+1 → open t+2) | 3.2% |
| ฉบับตรวจแล้ว net หลังต้นทุน 5 bps × 42 ครั้ง | 1.1% |

ส่วนต่าง 79 จุดเปอร์เซ็นต์มาจากการกำหนดเวลาอย่างเดียว กฎ SMA 20 วันเหมือนกันทุกบรรทัด ข้อมูลเป็น random walk ที่ไม่มีสัญญาณให้จับ ตัวเลข 82.3% จึงเป็นผลของ bug ล้วน ๆ

## Test สองแบบสำหรับ look-ahead {#lookahead-tests}

การอ่านโค้ดช่วยได้ แต่จับได้ไม่ครบ เราเขียน test ที่ถามคำถามเดียวว่า "ถ้าข้อมูลที่ยังไม่ควรรู้เปลี่ยนไป ผลที่รู้แล้วเปลี่ยนตามไหม"

**Test 1: แก้อนาคต** สุ่มเปลี่ยนราคาทุกแท่งหลังวัน k ผลตอบแทนที่รู้ครบแล้วภายในวัน k ต้องเหมือนเดิมทุกตัว

**Test 2: แก้ราคาปิดที่ใช้ตัดสินใจ** ลดเฉพาะ close วัน k ลงครึ่งหนึ่ง ผลตอบแทนที่ได้มาแล้วจนถึง close วัน k ต้องไม่เปลี่ยน เพราะการตัดสินใจจาก close k มีผลได้เฉพาะช่วงหลัง open k+1

| Test | ฉบับร่าง | ฉบับตรวจแล้ว |
| --- | --- | --- |
| 1. แก้ราคาหลังวัน 150 | ผ่าน | ผ่าน |
| 2. แก้ close วัน 150 อย่างเดียว | ไม่ผ่าน ผลช่วง close 149 → 150 เปลี่ยน | ผ่าน |

ฉบับร่างผ่าน test แรก เพราะมันไม่ได้มองวันพรุ่งนี้ มันใช้ราคาปิดของวันเดียวกับที่รับผลตอบแทน test แบบเดียวจึงไม่พอ ในบทต่อ ๆ ไปเราจะใช้ทั้งสองแบบกับ screener, pairs trading และโมเดล machine learning

$$
\text{ผลตอบแทนที่ถือ}_{t} = w_t \times \left(\frac{O_{t+2}}{O_{t+1}} - 1\right), \qquad w_t = f(C_0,\dots,C_t)
$$

สูตรนี้อ่านว่า น้ำหนัก $w_t$ คำนวณจากราคาปิดถึงวัน t เท่านั้น แล้วใช้กับช่วง open t+1 ถึง open t+2 ซึ่งตรงกับกติกาเวลาของ[บทที่ 3](#/chapter-13)

## ข้อผิดพลาดที่ AI ทำบ่อย {#common-mistakes}

รายการนี้มาจากการตรวจโค้ดร่างระหว่างเตรียมคอร์ส ไม่ได้มาจากการวัดทางสถิติ ใช้เป็น checklist ตอนอ่านโค้ด

1. **ใช้สัญญาณกับผลตอบแทนแท่งเดียวกัน** ดูว่ามี `shift` หรือ index t+1 อยู่ระหว่างสัญญาณกับผลตอบแทนไหม
2. **`dropna()` ทั้งตาราง** หุ้นที่เข้าตลาดทีหลังหรือถูกถอดออกจะหายไปทั้งตัว เป็นต้นเหตุหนึ่งของ survivorship bias ในบทที่ 6
3. **annualize ด้วย 365** ข้อมูลหุ้นรายวันในคอร์สนี้ใช้ 252 วันทำการ คริปโตที่ซื้อขายทุกวันเป็นอีกกรณีหนึ่ง
4. **คิด risk-free rate ผิดความถี่** อัตราดอกเบี้ยรายปี 5% ต้องแปลงเป็นรายวันก่อนหักจากผลตอบแทนรายวัน
5. **เวลาไม่มี timezone** ราคาหุ้นสหรัฐที่บันทึกเป็นเวลา UTC กับเวลา New York ตัดวันไม่ตรงกันบางช่วง บทที่ 2 ลงรายละเอียด
6. **ชื่อ parameter ของ API ที่ไม่มีจริง** AI อาจแต่งชื่อ argument ที่ฟังดูถูก ตรวจกับเอกสารทางการทุกครั้ง และรันกับข้อมูลจำลองก่อนต่อ API จริง
7. **ใส่ API key ในโค้ด** ให้อ่านจาก environment variable หรือไฟล์ `.env` ที่อยู่ใน `.gitignore` ห้ามวาง key ลงในแชตกับ AI

## ตรวจตัวเลขด้วยค่าที่คำนวณมือได้ {#known-answers}

วิธีที่เร็วที่สุดในการจับสูตรผิดคือป้อนข้อมูลที่เรารู้คำตอบล่วงหน้า เช่น ผลตอบแทน +1% กับ −1% สลับกัน 100 วัน มี sample standard deviation เท่ากับ $0.01\sqrt{100/99}$ เมื่อ annualize ด้วย $\sqrt{252}$ ได้ 0.1595 ถ้าโค้ดคืน 0.1920 แปลว่าใช้ 365 วัน

บัญชีต้นทุนก็ตรวจได้แบบเดียวกัน ถ้าน้ำหนักเปลี่ยน 42 ครั้ง ครั้งละ 5 bps ผลคูณ $(1+\text{gross}) \times (1-0.0005)^{42}$ ต้องเท่ากับ $1+\text{net}$ ตรงตัว Notebook ตรวจทั้งสองข้อด้วย `assert`

## Trial log เริ่มตั้งแต่วันแรก {#trial-log}

การให้ AI แก้กฎแล้วรันใหม่ใช้เวลาไม่กี่วินาที เราจึงลองได้หลายสิบแบบในบ่ายเดียว ถ้าไม่จด เราจะจำได้แต่แบบที่ผลดีที่สุด แล้วเข้าใจผิดว่ามันเป็นแบบแรกที่ลอง [บทที่ 5](#/chapter-15) แสดงว่าการเลือกผลดีที่สุดจากหลายครั้งทำให้ตัวเลขสูงเกินจริงเท่าไร

ทุกบรรทัดใน trial log มีอย่างน้อย กฎที่ลอง กติกาเวลา ต้นทุน ข้อมูลที่ใช้ ผล net และเหตุผลที่เก็บหรือทิ้ง

```json
{"trial": 1, "rule": "close > SMA20, long/cash", "fill": "open t+1 -> open t+2",
 "cost_bps": 5, "data": "synthetic seed 20261108", "net_return": 0.010842,
 "note": "first reviewed version; draft rejected for same-bar lookahead"}
```
