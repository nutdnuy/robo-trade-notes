# Welcome

เรียนรู้การสร้างระบบซื้อขายด้วย Python ตั้งแต่แนวคิดแรกจนถึงการดูแลระบบ ผ่านบทเรียนภาษาไทย 10 บท สมการที่อธิบายได้ และ Notebook ที่ลงมือทดลองต่อได้ด้วยตัวเอง

## เปิดบัญชี Webull และเตรียม API Key {#webull-start}

**[เปิดบัญชี Webull ผ่านลิงก์ QuantCorner →](https://www.webull.co.th/k/QuantCorner)**

ใช้ลิงก์แนะนำของ QuantCorner ด้านบน แล้วทำขั้นตอนเปิดบัญชีและยืนยันตัวตนบน Webull ตามเงื่อนไขที่แสดง ผู้ที่มีบัญชีอยู่แล้วเริ่มจากการเข้าสู่ระบบได้เลย

การเปิดบัญชีและการอนุมัติ OpenAPI เป็นคนละขั้นตอน ส่วนบทเรียนและห้องทดลองจำลองในเว็บนี้เริ่มเรียนได้โดยไม่ต้องมีบัญชี

### ขอ API Key ใน 5 ขั้นตอน

1. **เตรียมบัญชีและเข้าสู่ระบบ** เปิดบัญชีให้เรียบร้อย จากนั้นเข้า [เว็บไซต์ Webull Thailand](https://www.webull.co.th/) แล้วเลือก **Developer Tool** จากเมนูบัญชี
2. **สมัครสิทธิ์ OpenAPI** เข้า **API Management → My Application** กรอกข้อมูลและส่งคำขอ
3. **รอผลอนุมัติ** ตรวจสถานะใน **My Application** และอีเมล เมื่อ Webull อนุมัติแล้วจึงไปขั้นถัดไป
4. **ลงทะเบียนแอป** เข้า **API Management → API Keys Management** แล้วตั้งชื่อแอปสำหรับงานของคุณ
5. **สร้างและเก็บ Key** เลือก **Generate Key** และยืนยันตัวตนบน Webull ด้วยตนเอง จากนั้นเก็บ **App Key / App Secret** ในที่ปลอดภัย หลีกเลี่ยงการใส่ค่าจริงใน GitHub หรือ Notebook ที่แชร์

**[ดูวิธีขอ API Key แบบละเอียดในบทที่ 09 →](#/chapter-09/api-key)**

เว็บไซต์นี้ไม่รับ Key, Secret หรือ OTP ส่วนสิทธิ์ข้อมูลตลาดสำหรับ OpenAPI ต้องตรวจแยกจากการสมัครข้อมูลผ่านแอป Webull ตาม [Market Data API FAQ](https://developer.webull.co.th/apis/docs/market-data-api/faq/)

อ้างอิง [คู่มือ Webull Thailand: Individual Application Process](https://developer.webull.co.th/apis/docs/authentication/individual-application/) — ตรวจเอกสารวันที่ 13 กันยายน 2026 ชื่อเมนูและหน้าจอจริงอาจต่างจากคู่มือ

## เปลี่ยนความสงสัยให้เป็นสิ่งที่ทดสอบได้ {#welcome}

ถ้าเราเชื่อว่า “ราคาที่เริ่มเป็นขาขึ้นมีโอกาสขึ้นต่อ” เราจะนิยามคำว่าขาขึ้นอย่างไร ใช้ข้อมูลอะไร และจะรู้ได้อย่างไรว่าผลที่เห็นไม่ได้เกิดจากความบังเอิญ?

นี่คือจุดเริ่มต้นของ **Robo Trade หรือระบบซื้อขายตามกติกาที่กำหนดไว้** หนังสือออนไลน์เล่มนี้ชวนคุณเปลี่ยนแนวคิดให้เป็นขั้นตอนที่คอมพิวเตอร์ทำซ้ำได้ แล้วตรวจแต่ละขั้นด้วยข้อมูลและเหตุผล ตั้งแต่ราคาที่รับเข้ามา สัญญาณที่คำนวณ ไปจนถึงสถานะของคำสั่งและเงินสดในระบบ

โจทย์ของเราคือสร้างสิ่งที่ตรวจสอบได้ก่อน คุณจะพบทั้งตัวอย่างที่กติกาทำงานตามที่ออกแบบ และกรณีที่ผลทดสอบดูดีเกินจริงเพราะข้อมูลหรือสมมติฐานผิด

## เมื่ออ่านจบ คุณจะทำอะไรได้ {#learning}

- **เขียนกติกาที่ชัดเจน** แยกแนวคิด สัญญาณ สถานะเป้าหมาย คำสั่ง และรายการที่จับคู่สำเร็จ
- **ตรวจข้อมูลและเวลา** เลือกข้อมูลที่มีอยู่จริง ณ เวลาตัดสินใจ และอธิบายช่องว่างในข้อมูลได้
- **ทดสอบอย่างมีเหตุผล** คำนวณต้นทุน เปรียบเทียบกับเกณฑ์อ้างอิง และแยกช่วงสร้างแบบจำลองจากช่วงประเมินผล
- **จำลองระบบซื้อขาย** ติดตามเงินสด สถานะคงเหลือ การจับคู่บางส่วน และการป้องกันคำสั่งซ้ำ
- **อ่านเอกสาร Webull เป็น** เข้าใจส่วนที่เป็นกติกาของเรา และส่วนที่ต้องตรวจจาก API ของโบรกเกอร์
- **ออกแบบการดูแลระบบ** ตรวจข้อมูลล่าช้า กระทบยอดหลังเริ่มใหม่ และกำหนดเงื่อนไขหยุดที่ทดสอบได้

## วิธีเรียนให้ได้ประโยชน์ {#how-to-learn}

1. **อ่านคำถามและสมมติฐานก่อน** ลองคาดผลลัพธ์ด้วยเหตุผลของตัวเอง แล้วจึงดูโค้ด
2. **ทดลองเปลี่ยนทีละอย่าง** ใช้กราฟบนเว็บหรือ Notebook เพื่อดูว่าการเปลี่ยนกติกา เวลา หรือต้นทุนส่งผลอย่างไร
3. **ตรวจผล ไม่ใช่แค่ให้โค้ดรันผ่าน** ดูว่าหน่วย เวลา เงินสด และสถานะตรงกับสิ่งที่ตั้งใจไว้หรือไม่
4. **ตอบคำถามท้ายบท** อ่านเหตุผลของคำตอบ และจดว่ามีสมมติฐานใดที่คุณยังอธิบายไม่ได้

บทแรกเริ่มได้จากพื้นฐาน Python เล็กน้อย หากยังไม่คุ้นเคยกับตาราง pandas ให้เปิดบทที่ 02 ประกอบ ห้องทดลองบนเว็บใช้ข้อมูลจำลองและเริ่มได้ทันทีโดยไม่ต้องมีบัญชีซื้อขาย

Notebook ทุกบทมีข้อมูลอยู่ในตัวหรือใช้ตัวอย่างในชุดดาวน์โหลด และเก็บผลการรันไว้ให้อ่านได้ ตัวอย่างการวิจัยและจำลองทำงานออฟไลน์ การเชื่อมบัญชี Webull จริงต้องเตรียมสิทธิ์และตรวจเงื่อนไขบัญชีแยกต่างหากตามบทที่ 09
