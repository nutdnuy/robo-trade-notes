# จากข้อมูลราคา สู่สัญญาณแรก

เริ่มสร้าง Robo Trade ด้วย Python และ Webull OpenAPI เข้าใจข้อมูล ออกแบบกติกา และเห็นผลผ่านการทดลองด้วยตัวเอง

## ระบบที่ดี เริ่มจากกติกาที่ชัดเจน {#overview}

“ถ้าราคามีแนวโน้มขึ้น เราจะซื้อ” ฟังดูเป็นกลยุทธ์ แต่คอมพิวเตอร์ยังทำตามไม่ได้ เพราะคำว่า **แนวโน้มขึ้น** ยังไม่มีนิยาม บทนี้จะเปลี่ยนความคิดนั้นให้เป็นเงื่อนไขที่คำนวณซ้ำได้ โดยใช้ค่าเฉลี่ยเคลื่อนที่สองเส้นเป็นตัวอย่าง

เราจะใช้ Webull OpenAPI เป็นช่องทางรับข้อมูล แล้วให้ Python ทำหน้าที่จัดระเบียบข้อมูลและคำนวณสัญญาณ แนวทางนี้ต่อยอดจากหัวข้อข้อมูลการเงินและ SMA ในหนังสือ *Python for Algorithmic Trading* โดยปรับตัวอย่างและเขียนโค้ดใหม่สำหรับบทเรียนนี้ [แหล่งอ้างอิง 1](#references)

> **เมื่อเรียนจบ คุณจะทำได้**
>
> - อธิบายความต่างของข้อมูลราคา สถานะเป้าหมาย และคำสั่งซื้อขาย
> - อ่านโครงสร้าง Historical Bars ของ Webull และจัดข้อมูลตามเวลา
> - คำนวณ SMA สองช่วง และตรวจสัญญาณโดยไม่ใช้ข้อมูลอนาคต

**ก่อนเริ่ม:** อ่านตัวแปร ฟังก์ชัน และตาราง pandas ได้บ้างก็เพียงพอ ห้องทดลองบนหน้านี้ใช้ได้ทันทีโดยไม่ต้องมีบัญชี Webull

## เริ่มต้นกับ Webull API {#webull}

OpenAPI ช่วยให้โปรแกรมเรียกข้อมูลและบริการของ Webull ได้โดยตรง บทนี้เลือกใช้ **Market Data API** สำหรับราคาย้อนหลังของหุ้นสหรัฐฯ ส่วนการส่งคำสั่งซื้อขายอยู่ใน Trading API ซึ่งเป็นอีกส่วนหนึ่งของระบบ [แหล่งอ้างอิง 2](#references)

| ส่วนของ API | หน้าที่ |
| --- | --- |
| Market Data | รับราคาเปิด สูงสุด ต่ำสุด ปิด และปริมาณการซื้อขายมาวิเคราะห์ |
| Trading | จัดการคำสั่งและบัญชี ใช้เมื่อออกแบบการส่งคำสั่งและการควบคุมความเสี่ยงแล้ว |

### เตรียมสภาพแวดล้อมให้ตรงกัน

ใช้ Python 3.11 หรือ 3.12 สำหรับแบบฝึกหัดนี้ ติดตั้ง SDK ทางการและ pandas ใน virtual environment ของโปรเจกต์ คุณต้องมี App Key / App Secret ของสภาพแวดล้อมที่เลือก และสิทธิ์ Market Data สำหรับ OpenAPI โดยเฉพาะ สิทธิ์ดูราคาในแอปไม่ใช่สิทธิ์เดียวกับ OpenAPI [แหล่งอ้างอิง 2–3](#references)

```shell
python -m venv .venv
source .venv/bin/activate  # Windows: .venv\Scripts\activate
python -m pip install webull-openapi-python-sdk==3.0.0 pandas==2.3.2
```

| สภาพแวดล้อม | Endpoint | ใช้เมื่อ |
| --- | --- | --- |
| UAT / Test | `th-api.uat.webullbroker.com` | พัฒนาและตรวจการเชื่อมต่อ |
| Production | `api.webull.co.th` | ใช้งานกับสิทธิ์และข้อมูลจริง |

ปลายทางจากคู่มือ SDK ของ Webull Thailand [แหล่งอ้างอิง 3](#references) UAT เป็นระบบทดสอบของผู้ให้บริการ ส่วนข้อมูลจำลองในห้องทดลองนี้สร้างขึ้นเองในเครื่อง

### ให้ SDK จัดการการลงนามคำขอ

เก็บกุญแจไว้ใน environment variables บนเครื่องที่รัน Python ตัวอย่างใช้ `ApiClient` ร่วมกับ `DataClient` และเรียก `get_batch_history_bar` เพื่อรับข้อมูลหุ้นหนึ่งตัวในรูปแบบ batch SDK จัดการการลงนามและขั้นตอน Token ให้ โดยผู้ใช้ทำ 2FA ตามที่ Webull ร้องขอ [แหล่งอ้างอิง 4–5](#references)

::: api-example

> **กุญแจ API อยู่ฝั่ง Python เท่านั้น**
>
> เว็บบทเรียนนี้ไม่รับและไม่เก็บ App Secret ดาวน์โหลดสคริปต์ฉบับเต็มท้ายบทเพื่อรันบนเครื่องของคุณ ตัวอย่างตั้งต้นที่ UAT และจะไม่เรียกเครือข่ายจนกว่าจะระบุ `--fetch`

## อ่านข้อมูลราคาให้ถูกต้อง {#data}

**หนึ่งแท่งราคา คือข้อมูลของหนึ่งช่วงเวลา** ในบทนี้ใช้ `timespan="D"` สำหรับแท่งรายวัน และเลือก `trading_sessions="RTH"` สำหรับช่วงซื้อขายปกติ ข้อมูลที่ API ส่งกลับมีโครงสร้างระดับหุ้นและระดับแท่งราคาแยกกัน [แหล่งอ้างอิง 6](#references)

| ฟิลด์ | ความหมาย | ก่อนนำไปใช้ |
| --- | --- | --- |
| `time` | เวลาของแท่งใน UTC | แปลงเป็นเวลาที่มี timezone แล้วเรียงจากเก่าไปใหม่ |
| `open / high / low / close` | ราคา OHLC ของแท่ง | API ระบุเป็น string จึงต้องแปลงเป็นตัวเลข |
| `volume` | ปริมาณการซื้อขาย | ตรวจค่าที่หายไปและค่าที่ผิดปกติ |

**โครงสร้างตอบกลับ — ค่าจำลองเพื่ออธิบาย**

```json
{
  "result": [{
    "symbol": "DEMO",
    "instrument_id": "SYNTHETIC",
    "result": [{
      "time": "2026-01-05T21:00:00+0000",
      "open": "100.00",
      "high": "101.20",
      "low": "99.60",
      "close": "100.80",
      "volume": "120000"
    }]
  }]
}
```

ความผิดพลาดที่พบได้ง่ายคือคำนวณบนข้อมูลที่เรียงย้อนเวลา มีแถวซ้ำ หรือแท่งล่าสุดยังไม่จบ ตัวแปร `real_time_required` มีคำอธิบายเฉพาะใน API Reference จึงไม่ควรเดาความหมายจากชื่อเพียงอย่างเดียว ตัวอย่างตั้งเป็น `True` ตามคำอธิบายเรื่องแท่งที่เสร็จแล้ว และยังต้องตรวจเวลาปิดแท่งตาม session จริงก่อนใช้งาน [แหล่งอ้างอิง 6](#references)

> **ลองคิดก่อนอ่านต่อ**
>
> ถ้าแท่งล่าสุดยังไม่ปิด ค่า SMA และสัญญาณของคุณจะเปลี่ยนระหว่างวันได้หรือไม่?

::: bar-question

## เปลี่ยน “แนวโน้ม” ให้เป็นกติกา {#strategy}

**Simple Moving Average (SMA)** คือค่าเฉลี่ยราคาปิดย้อนหลังจำนวน *n* แท่ง โดยให้น้ำหนักแต่ละแท่งเท่ากัน เช่น SMA 5 ของราคาปิด 100, 102, 101, 103, 104 เท่ากับ **102**

::: sma-formula

เส้นระยะสั้นตอบสนองต่อการเปลี่ยนแปลงของราคาล่าสุดมากกว่าเส้นระยะยาว เราจะใช้ความสัมพันธ์ของสองเส้นเป็น **กติกาตัวอย่าง** แบบ Long/Cash โดยไม่ขายชอร์ต และไม่อ้างว่าเป็นค่าพารามิเตอร์ที่ดีที่สุด [แหล่งอ้างอิง 1](#references)

| เงื่อนไข | สถานะเป้าหมาย |
| --- | --- |
| SMA สั้น > SMA ยาว | `1` หรือ LONG |
| SMA สั้น ≤ SMA ยาว | `0` หรือ CASH |
| ข้อมูลยังไม่ครบช่วงระยะยาว | อยู่ในช่วง warm-up และยังไม่ประเมินสัญญาณ |

::: sma-example

`target` คือสถานะที่กติกาต้องการหลังเห็นราคาปิด ส่วน `next_open_target` เป็นการเลื่อนเป้าหมายไปแท่งถัดไป ยังไม่ใช่ตำแหน่งถือครองที่ยืนยันจากโบรกเกอร์

## ทดลอง แล้วสังเกตด้วยตัวเอง {#lab}

เริ่มจาก SMA 5 และ 20 แท่ง จากนั้นเปลี่ยนทีละค่า สังเกตว่าเส้นเฉลี่ยและจุดเปลี่ยนสถานะขยับอย่างไร ข้อมูลเดิมจะคงที่ตลอด เพื่อให้เราเปรียบเทียบผลของพารามิเตอร์ได้อย่างตรงไปตรงมา

::: lab

### แบบฝึกหัด: เปลี่ยนเส้นยาวจาก 20 เป็น 40 แท่ง

ช่วง warm-up ยาวขึ้นเท่าไร? จุดเปลี่ยนสถานะเกิดช้าลงทุกครั้งหรือไม่? จดเลขแท่งอย่างน้อยสองจุดเพื่อสนับสนุนคำตอบ แทนการสรุปจากความรู้สึกว่าเส้น “ดูเรียบขึ้น”

## สัญญาณไม่ใช่คำสั่งซื้อ {#timing}

เมื่อโค้ดให้ค่า LONG เรารู้เพียงว่าเงื่อนไขที่ตั้งไว้เป็นจริง ยังไม่มีการกำหนดจำนวนหุ้น ตรวจเงินสด ส่งคำสั่ง หรือรับผลจับคู่ การแยกขั้นตอนเหล่านี้ทำให้ตรวจระบบได้ว่าเกิดความผิดพลาดตรงไหน

> **เห็นราคาปิดแท่ง t แล้ว ย้อนกลับไปซื้อที่ราคาเปิดแท่ง t ไม่ได้**
>
> สมมติว่ารู้สัญญาณหลังปิดแท่งที่ 25 เป้าหมายนี้จึงเริ่มใช้วางแผนคำสั่งที่แท่ง 26 หรือเวลาที่ซื้อขายได้จริงภายหลัง การนำมันไปคูณผลตอบแทนที่เกิดก่อนรู้สัญญาณ คือการใช้ข้อมูลอนาคต หรือ **look-ahead bias**

การใช้ `shift(1)` ช่วยเลื่อนสถานะเป้าหมายในตาราง แต่ไม่ได้แก้ปัญหาการจำลองซื้อขายทั้งหมด ยังต้องกำหนดราคาเข้าซื้อที่เป็นไปได้ ต้นทุน spread, slippage และกฎการจับคู่ด้วย บทนี้จึงหยุดที่การสร้างสัญญาณ ไม่รายงานผลตอบแทนที่ยังไม่ได้จำลอง

| สิ่งที่ได้ในบทนี้ | สิ่งที่ต้องทำก่อนประเมินกลยุทธ์จริง |
| --- | --- |
| กติกา SMA ที่คำนวณซ้ำได้ | กำหนดสมมติฐานการจับคู่และต้นทุน |
| ตำแหน่งเวลาที่เกิดสัญญาณ | จำลองเงินสด จำนวนหุ้น และข้อจำกัดการซื้อขาย |
| การทดลองกับข้อมูลสังเคราะห์ | ใช้ข้อมูลที่ตรวจสอบแล้ว และแบ่งช่วงทดสอบนอกตัวอย่าง |
