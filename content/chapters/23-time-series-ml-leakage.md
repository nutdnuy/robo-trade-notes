# Time Series และ Machine Learning: กับดัก Leakage

การให้ AI เขียนโมเดล machine learning ทำนายราคาใช้เวลาไม่ถึงนาที โค้ดที่ได้มักใช้ `train_test_split` สุ่มแบ่งข้อมูล ฝึกโมเดล แล้วรายงาน accuracy ที่ดูดีเกินคาด บทนี้แสดงว่าตัวเลขแบบนั้นเกิดได้แม้กับข้อมูลที่ไม่มีอะไรทำนายได้เลย

หลังจบบท ผู้เรียนจะอธิบายได้ว่าทำไมการสุ่มแบ่งข้อมูลอนุกรมเวลาถึงรั่ว ใช้การแบ่งตามเวลาพร้อม purge จับ feature ที่แอบใช้อนาคตด้วย test จาก Prework P1 และอ่าน accuracy เทียบกับ standard error แทนการเทียบกับความรู้สึก

## สุ่มแบ่งข้อมูลแล้ว accuracy 76.8% {#random-split}

ใช้ `train_test_split` แบบสุ่มกับข้อมูล white noise ได้ผลดังนี้

| วิธีแบ่ง | train | test | accuracy |
| --- | --- | --- | --- |
| สุ่มแบ่ง 80/20 | 1,208 | 302 | 76.8% |
| แบ่งตามเวลา พร้อม purge 20 วัน | 1,188 | 302 | 46.4% |

standard error ของ accuracy ที่ 302 แถว คือ $\sqrt{0.5 \times 0.5 / 302} \approx 2.9\%$ ผลจากการแบ่งตามเวลาจึงอยู่ห่างจาก 50% ราว 1.2 standard error ซึ่งแยกจากการเดาไม่ออก ตรงกับความจริงที่เรารู้ ส่วนผลจากการสุ่มแบ่งห่างจาก 50% เกือบ 9 standard error ทั้งที่ไม่มีอะไรให้ทำนาย

## ทำไมการสุ่มแบ่งถึงรั่ว {#why-random-leaks}

สาเหตุมีสองชั้นที่ทำงานพร้อมกัน

**Label ทับกัน** label ของวัน t ใช้ผลตอบแทนวัน t+1 ถึง t+20 ส่วน label ของวัน t+1 ใช้วัน t+2 ถึง t+21 สองค่านี้ใช้ผลตอบแทน 19 วันร่วมกัน ใน Notebook label ของวันติดกันตรงกัน 89.2% ของวัน

**Feature ต่อเนื่อง** ผลตอบแทนย้อนหลัง 60 วันของวัน t กับ t+1 ต่างกันเพียงวันเดียวที่เข้าและวันเดียวที่ออก feature ของวันติดกันจึงแทบเหมือนกัน

เมื่อสุ่มแบ่ง แถวทดสอบเกือบทุกแถวมีวันข้าง ๆ อยู่ในชุดฝึก Notebook วัดว่าแถวฝึกที่ใกล้ที่สุดของแถวทดสอบอยู่ห่างกันกี่วัน ค่ากลางคือ 2 วัน โมเดลจึงไม่ได้เรียนรู้รูปแบบอะไร มันลอกคำตอบจากวันข้าง ๆ ซึ่งรู้ผลตอบแทน 18 จาก 20 วันของแถวทดสอบแล้ว

### การแบ่งตามเวลาและ purge

การแบ่งที่ถูกต้องฝึกด้วยอดีต แล้วทดสอบกับอนาคตเท่านั้น และต้องตัดแถวฝึกช่วงท้ายที่ label ยังยื่นเข้าไปในช่วงทดสอบ เรียกว่า purge แถวฝึกวันที่ t ใช้ผลตอบแทนถึงวัน t+20 ถ้าวันแรกของช่วงทดสอบอยู่ภายใน 20 วันหลัง t แถวนั้นต้องออก บางงานเพิ่ม embargo คือเว้นช่วงหลังชุดทดสอบด้วย ในกรณีที่สลับลำดับชุดฝึกและชุดทดสอบใน cross-validation

`TimeSeriesSplit` ของ scikit-learn แบ่งตามเวลาให้ และมี argument `gap` สำหรับเว้นช่วง ให้ตั้ง `gap` อย่างน้อยเท่ากับ horizon ของ label

## Feature ที่แอบใช้อนาคต {#leaky-feature}

การแบ่งตามเวลาแก้ได้แค่ปัญหาเรื่องการแบ่ง ถ้าตัว feature ใช้อนาคต ผลก็ยังรั่ว ตัวอย่างที่พบบ่อยคือค่าเฉลี่ยแบบ centred window เช่น `rolling(21, center=True)` ใน pandas ซึ่งให้เส้นเรียบสวยบนกราฟ แต่ค่าของวัน t ใช้ข้อมูลวัน t+1 ถึง t+10

| feature ชุดที่ 4 | แบ่งตามเวลา | accuracy |
| --- | --- | --- |
| volatility 60 วันย้อนหลัง | ใช่ | 46.4% |
| ค่าเฉลี่ย centred 21 วัน | ใช่ | 61.9% |

Test 1 จาก[Prework P1](#/chapter-16) จับได้ทันที เปลี่ยนผลตอบแทนทุกวันหลังวัน t แล้วดูว่า feature ของวัน t เปลี่ยนไหม feature ที่ถูกต้องไม่เปลี่ยน feature แบบ centred เปลี่ยน ใช้ test นี้กับทุก feature ก่อนฝึกโมเดล โดยเฉพาะ feature ที่ AI สร้างให้

leakage แบบอื่นที่ควรตรวจ

1. **Standardize ด้วยข้อมูลทั้งหมด** ค่าเฉลี่ยและ standard deviation ต้องมาจากชุดฝึกเท่านั้น Notebook ใช้ `standardize(train, test)` ที่คำนวณจากชุดฝึก
2. **เลือก feature จากผลบนชุดทดสอบ** ลองหลาย feature แล้วเก็บชุดที่ accuracy ในชุดทดสอบสูงสุด ชุดทดสอบก็กลายเป็นชุดฝึกแล้ว
3. **ข้อมูลที่ประกาศช้า** ใช้กำไรไตรมาสตั้งแต่วันสิ้นไตรมาส ทั้งที่บริษัทประกาศหลังจากนั้นหลายสัปดาห์ ตาม[บทที่ 2](#/chapter-18)
4. **Universe ปัจจุบัน** ฝึกโมเดลเฉพาะหุ้นที่ยังอยู่วันนี้ ตาม[บทที่ 6](#/chapter-19)

## Walk-forward กับสัญญาณเล็ก {#walk-forward}

ข้อมูลชุดที่สองฝัง autocorrelation 0.08 ไว้โดยตั้งใจ ผลตอบแทนวันนี้บอกทิศของวันพรุ่งนี้ได้เล็กน้อย เราใช้ walk-forward ทุก 200 วัน ฝึกใหม่ด้วยข้อมูลที่ผ่านมาทั้งหมด แล้วทำนาย 200 วันถัดไป ไม่มีแถวทดสอบไหนอยู่ในชุดฝึกของตัวเอง

| | ค่า |
| --- | --- |
| วันที่ทำนายนอกชุดฝึก | 2,979 |
| accuracy | 52.2% |
| ช่วง 50% ± 2 standard error | 48.2% ถึง 51.8% |

52.2% อยู่นอกช่วงสองเท่าของ standard error เล็กน้อย เป็นผลจริงที่ฝังไว้ แต่ยังเล็กมาก ข้อมูลจริงที่มีสัญญาณระดับนี้มักไม่พอจ่ายต้นทุน เพราะกฎที่ทำนายรายวันต้องซื้อขายแทบทุกวัน ก่อนเชื่อ accuracy ระดับนี้ ให้แปลงเป็นผลตอบแทน net ด้วยต้นทุนแบบเดียวกับบทที่ 3 และนับจำนวนโมเดลที่ลองไว้ใน trial log

## เลือกโมเดลอย่างไร {#model-choice}

ปัญหาของบทนี้ไม่ได้อยู่ที่ k-nearest neighbours โมเดลที่ซับซ้อนกว่า เช่น random forest หรือ neural network รั่วได้มากกว่า เพราะจำรายละเอียดของวันข้าง ๆ ได้ดีกว่า ลำดับที่ใช้ในคอร์สคือ

1. เริ่มจาก baseline ที่ไม่ต้องฝึก เช่น ทำนายว่าขึ้นทุกวัน หรือใช้เครื่องหมายของผลตอบแทนวันนี้
2. ใช้โมเดลเชิงเส้นที่มี feature น้อย เพราะอ่านค่า coefficient ได้และ overfit ยากกว่า
3. ใช้โมเดลที่ซับซ้อนขึ้นเมื่อผ่านสองขั้นแรกแล้ว และต้องชนะ baseline ในช่วง walk-forward หลังหักต้นทุน
